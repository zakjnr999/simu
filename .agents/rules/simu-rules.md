# SIMU — MASTER PRODUCT RULE

This is the highest-level rule for the Simu project.

It applies to all Simu development, design, UI generation, screen generation, feature development, and product decisions.

## PRODUCT IDENTITY

Simu is an interactive skill-practice platform.

Simu is NOT:
- a generic AI chatbot
- a conventional e-learning app
- a corporate SaaS dashboard
- a collection of static lessons

The core experience is:

ENTER A REALISTIC SITUATION
→ INTERACT
→ RESPOND / MAKE DECISIONS
→ AI REACTS
→ RECEIVE FEEDBACK
→ EARN XP / REWARDS
→ IMPROVE
→ UNLOCK THE NEXT CHALLENGE

Simu should feel like:

GAME + REALISTIC SIMULATION + PERSONAL DEVELOPMENT.

Interaction is the core product.

## PRODUCT PRINCIPLE

Simu should not feel like a learning app that happens to contain games.

It should feel like an interactive world where users improve real skills by participating in realistic situations.

Prefer:
DOING over READING
EXPERIENCING over WATCHING
INTERACTING over FORM FILLING
PROGRESSING over BROWSING

## VISUAL IDENTITY

Simu uses a LIGHT visual system.

The visual language should be:

- bright
- playful
- premium
- tactile
- optimistic
- modern
- expressive
- game-like

Prefer:
- warm white
- cream
- pastel backgrounds
- purple
- soft blue
- mint
- yellow
- orange
- rounded surfaces
- soft depth
- polished 3D illustrations
- expressive characters
- playful typography

Never randomly introduce:
- dark UI
- cyberpunk
- neon AI aesthetics
- generic SaaS styling
- generic dashboard styling
- boring Material styling

## MASCOT

Simu has ONE PRIMARY MASCOT.

The current primary mascot is a CORGI / PUPPY.

This mascot must remain visually and conceptually consistent across the product.

The mascot can appear as:
- guide
- companion
- reaction character
- encouragement
- celebration
- loading character
- empty-state character
- progression character
- achievement character

Do not replace the primary mascot with another animal.

## GAME-LIKE EXPERIENCE

Simu should use game mechanics where they improve the experience.

Examples:
- XP
- levels
- streaks
- quests
- challenges
- checkpoints
- progression paths
- unlocks
- badges
- achievements
- rewards
- reactions
- celebrations

Do not force game mechanics into places where they do not make sense.

## INTERACTION FIRST

For every screen ask:

"What does the user DO here?"

Prefer interaction over passive information.

Examples:

Information → interactive choice

Progress → visual journey

Feedback → drill

Completion → reward

Navigation → progression

## TYPOGRAPHY

Typography must have personality.

Use a rounded, expressive, highly readable typography system.

Major headings should feel:
- bold
- friendly
- playful
- distinctive

Avoid generic-looking application typography.

Do not sacrifice readability for style.

## DESIGN CONSISTENCY

Every new Simu screen must feel like it belongs to the same product.

Do not introduce a different:
- mascot style
- illustration style
- typography style
- card language
- button language
- color system
- icon language

without an explicit product decision.

## DO NOT INVENT PRODUCT DIRECTION

Do not silently introduce:
- new mascots
- unrelated features
- new visual identities
- random game mechanics
- major navigation changes
- unrelated product categories

When something is unspecified, preserve the existing Simu direction.

## NORTH STAR

"Make users feel like they are stepping into a situation and actively practicing it — not completing another lesson."
